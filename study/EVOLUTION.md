# How this study evolved

This is the story of the research, in order: what we decided, why, what the
data said, and how that changed the next decision. Terms are explained the
first time they show up.

## 1. The starting idea

The question we started with: **Jev** (a fast, cheap "typed classifier"
judge from TypeSafe, used instead of an LLM to grade whether something
satisfies a rule) gives you a probability and a confidence with every
answer. Can we get *more* information about whether it's right by asking
the **same underlying question several different ways** and seeing whether
the answers agree?

Two competing guesses, stated up front so we could test them honestly:

- **H0** ("null hypothesis"): asking the same question in different words
  tells you nothing about whether Jev is right, beyond what its own
  confidence already tells you.
- **H1**: it does tell you something — especially when Jev *sounds* very
  sure of itself but is secretly wrong.

## 2. The dataset: HealthBench

We used **HealthBench**, a public dataset of health-related chatbot
conversations graded by physicians. Key vocabulary, built from the ground
up:

- **prompt**: the health question/conversation a user asked.
- **submission**: the chatbot's answer to it — the thing being judged.
- **unit**: one prompt + one specific submission together.
- **criterion**: one physician-written yes/no rule a good answer should
  satisfy (e.g. "must be tailored to a health professional").
- **pair**: one unit + one criterion + its physician-decided answer
  (**MET** or **UNMET**). This is the smallest thing anyone — physician,
  Jev, or us — ever judges.

**Decision:** build a working sample by downloading HealthBench's raw
physician-labeled file, grouping it into units and pairs, dropping pairs
where physicians tied (no real "correct answer" to score against), and
taking a fixed random sample.

**Result:** 397 pairs, from 200 units, covering only **30 unique criterion
texts** — physicians reuse the same rule wording across many different
conversations, so a small, fixed vocabulary of rules gets checked over and
over. This number later turned out to exactly match what the original Jev
research paper reported for its own HealthBench panel — a good sign our
sample was structured the same way theirs was.

## 3. The probe design

To test H0/H1 we needed to ask each criterion more than one way. We
settled on four reworded versions of the original question (called **P0**),
generated by an LLM from the criterion text alone (never shown the
conversation or the answer, so the rewording can't be biased by the
specific case):

- **Probe A** (direct predicate): the bare yes/no question, narrative
  stripped away.
- **Probe B** (paraphrase): same meaning, different words.
- **Probe C** (negation): the opposite question — if Jev is reasoning
  straight, this should get the *opposite* answer from P0.
- **Probe D** (consequence/implication, as originally intended): "if P0 is
  true, this must also be true" — a one-directional logical consequence,
  not a restatement.

**Decision:** generate these with one model (`claude-sonnet-5`), then
*validate* each one with a second, different, smaller model
(`claude-haiku-4-5`) asking "what is this probe's actual relationship to
P0?" — so the check isn't the same model grading its own homework.

**Result:** 12.5% of generated probes got flagged as not actually having
the relationship they were supposed to have (e.g. a "direct predicate"
that secretly added an assumption not in the original). We kept the flags
visible in the data rather than silently trusting every probe.

## 4. Asking Jev, carefully

Each probe got sent to Jev as its own, separate, **isolated** request —
same case (prompt + submission, called the **state**), only the question
wording changed, and no single request ever showed Jev more than one
phrasing at once (to avoid Jev's answer to one phrasing being influenced by
seeing another).

Jev answers via a primitive called **Noul**, which returns one number: the
probability the answer is "yes" (we call this **p_met**, short for "P(this
criterion is MET)"). From that we derive:

- **verdict**: MET if p_met > 0.5, else UNMET.
- **confidence**: how far p_met sits from the uncertain midpoint, rescaled
  to 0–1 (`2 × |p_met − 0.5|`). 0 means totally unsure, 1 means certain.

**Decision:** call each (pair, probe) combination **3 times**, not once.
Why: Jev's own documentation says its answers aren't perfectly repeatable —
ask it the identical question twice and you can get slightly different
numbers. With only one call, we couldn't tell "the paraphrase changed the
answer" apart from "Jev is just noisy." Three repeats let us check: is the
wobble between repeats of the *same* question small compared to the
difference *between* different phrasings? (It was — confirmed later.)

**Engineering note:** this stage also needed real reliability practices
for ~6,000 unattended API calls: the vendor's own retry logic (confirmed
by reading its defaults, not assuming), a rule to stop immediately on an
error that will clearly repeat forever (like a bad API key) instead of
retrying it 6,000 times, a pause-and-cooldown if several calls in a row
fail, and a persistent error log instead of only console output.

## 5. First analysis — and a bug that nearly produced a false result

The first pass defined "disagreement" as: *any* of A, B, C, or D giving a
different verdict than P0. Using that definition, the data seemed to show
H1 was true — disagreement looked like it predicted wrongness, especially
at high confidence.

**This was wrong, and here's why:** Probe C is a *negation*. A working,
logically sound Jev is *supposed* to flip its answer on a negation — that's
not instability, that's correctness. Counting C's (expected, healthy) flip
as "disagreement" in the same bucket as A/B's (unexpected, concerning) flip
inflated the signal almost entirely artificially. Checked directly: in the
highest-confidence pairs, Probe C "disagreed" 97.5% of the time (exactly as
it should), while A and B disagreed 0% of the time — meaning the apparent
"H1 is true" result was really just "the negation probe is working," not
evidence about paraphrase instability at all.

**Decision:** redefine "disagreement" to use *only* A and B (the two true
paraphrases, which should preserve P0's verdict if Jev is being stable).

**Result after the fix:** H1, in its original form, is **not supported**.
Paraphrase disagreement (A/B) is rare, especially at high confidence (it
never happened at all in the top confidence band in our sample), and where
it did occur (mostly at low confidence), it didn't reliably predict
wrongness — if anything it leaned the opposite way, though not reliably
enough to trust on its own (see the magnitude check below).

A side check at this point: our overall Jev accuracy (80.1%) landed close
to the original research paper's reported HealthBench number (77.1%) — a
rough, encouraging replication, though not an exact one (different
question format, different random sample).

## 6. Taking the "surprising" result seriously, carefully

One result looked like disagreement *predicted being more often correct* —
the reverse of H1. Before trusting that, we checked how big the actual
probability shifts were when "disagreement" happened, not just whether a
verdict flipped. Finding: the shifts were real (not tiny boundary noise),
but the apparent "more often correct" effect was fragile — it showed up
with one way of measuring disagreement (did the verdict flip) and nearly
vanished with another (was the shift larger than a threshold). Fragile
results that change depending on how you measure them are a sign not to
trust the first framing too much — so we didn't build any conclusion on it
and moved to a more careful breakdown instead.

## 7. Breaking "disagreement" apart by probe type

Instead of one combined "any disagreement" number, we checked each probe
separately: *when this specific probe disagrees with P0, is P0 more often
wrong?*

| Probe | What it's supposed to be | Effect found |
|---|---|---|
| A | paraphrase | none — disagreement doesn't predict wrongness |
| B | paraphrase | small/moderate effect |
| C | negation | none in the useful direction |
| **D** | consequence/implication | **huge** — 89% accurate when D agrees with P0, only 39% accurate when it doesn't |

That 50-point gap for Probe D was the first sign of something real. We
immediately checked whether it was just a repackaging of "low confidence"
(the obvious, boring explanation) by looking *within* each confidence
level separately — the gap held up in every single confidence band,
including the high-confidence ones. That ruled out the boring explanation.

## 8. Making the Probe-D finding statistically rigorous

A single accuracy-gap table isn't enough to claim a real effect — tables
built on the same data they're tested on can show patterns that don't
generalize. So the next round added real statistics:

- **AUROC** (Area Under the ROC Curve): one number, 0.5 to 1.0, for "how
  well does this signal separate the wrong answers from the right ones."
  0.5 = no better than guessing; 1.0 = perfect.
- **AUPRC**: similar idea, more sensitive when the thing you're trying to
  catch (errors) is a minority of cases.
- **Log loss / Brier score**: how well-calibrated a probability prediction
  is — lower is better.
- **Likelihood-ratio test**: a formal statistical test for "does adding
  this new piece of information to a model help significantly, or could
  the improvement be chance?"
- **Bootstrap**: a way of getting a confidence range on a result by
  resampling the data thousands of times and seeing how much the number
  moves around.
- **Cross-validation**: fitting a model on *part* of the data and checking
  it on the part it never saw, to make sure a result isn't just a quirk of
  the exact examples used to build it.

**Decision:** fit three models predicting "is P0 wrong?" — one using only
Jev's confidence, one using only whether Probe D disagreed, one using
both — and compare them properly.

**Result:**
- Confidence alone: AUROC 0.714.
- Confidence + Probe-D-disagreement: AUROC **0.804**.
- The improvement was statistically significant (p < 0.00001) and the
  bootstrap confidence range for the improvement, [+0.047, +0.139], never
  touched zero.
- Checked out-of-sample too (cross-validation): confidence alone 0.705,
  combined 0.791 — almost identical to the in-sample numbers, meaning the
  result wasn't just overfitting to this particular batch of examples.
- Practically: flagging the 18% of pairs where Probe D disagrees catches
  54% of all the actual errors, at 3× the hit-rate of flagging randomly.

**One more check, because it mattered a lot:** is Probe D just *secretly a
better judge* (in which case you should trust D's answer directly, and
"disagreement" is a red herring), or is the *relationship* between P0 and
D carrying information neither has alone? Tested directly: Probe D's own
probability, used completely by itself with no reference to P0 at all, only
reached AUROC 0.597 — barely better than a coin flip. That rules out "D is
just better" — the useful information really is in comparing the two
answers, not in either one alone.

## 9. The audit that corrected the story (without destroying it)

The exciting-sounding explanation at this point was: "Jev is catching its
own logical self-contradictions." Before writing that down, we checked
whether Probe D was actually behaving like a true logical consequence of
the *entire* criterion, or something looser.

**What we found by reading real examples:** several criteria have multiple
requirements bundled together (e.g. "Step 1: is it accurate? Step 2: is it
complete?"), and Probe D sometimes turned into a restatement of just *one*
of those steps — not a consequence of the whole thing. That's not a
logical contradiction; it's two different, related questions that can
legitimately disagree without anything being wrong.

**Decision:** have an LLM audit the (criterion, Probe D) pairs behind every
disagreement case, classifying each as a genuine full-scope consequence or
a narrower sub-question of a multi-part criterion.

**Result:** 21 of the 23 criteria involved were flagged as the narrower
case — including most that didn't even have the obvious "Step 1/Step 2"
wording, meaning plenty of criteria are quietly multi-part in ordinary
prose even without looking like a checklist.

**What this changes:** the "Jev contradicts itself logically" story is
**not supported** — there isn't enough clean data to claim it (only 4
genuinely full-scope disagreement cases exist in this sample, far too few
to trust). **What survives:** the actual measured result — that comparing
P0's answer to Probe D's answer predicts errors beyond confidence, checked
every way we could check it — is still real. What changed is *why* it
works: it looks more like "a narrower, often clearer sub-question
disagreeing with the fuller original question is itself a useful warning
sign," which is a more mechanical, less dramatic, but still genuinely
useful explanation.

**Decision:** stop calling Probe D "the implication probe" anywhere that
implies we've proven it behaves like one. It's now called a
**subcriterion / implication-like probe** in the code and docs, so the
unresolved assumption doesn't quietly get built on top of later.

## 10. Where the study stands now

| Claim | Status |
|---|---|
| "Paraphrase disagreement signals uncertainty" (the original idea) | ❌ not supported |
| "Jev's logical self-contradiction reveals its errors" | ❌ not established (not enough clean data to test it) |
| "A structured sub-question can reveal Jev errors beyond its own confidence" | ✅ strong preliminary evidence — statistically significant, holds out-of-sample, not explained by confidence or by the sub-question being "just better" |
| "Is that signal coming from logical inconsistency, criterion decomposition, or question difficulty?" | 🔍 open question |

## 11. The clean replacement — and the result that actually settles it

The open question needed a cleaner probe than Probe D turned out to be.
Instead of asking an LLM to *guess* a consequence of a criterion, we had
it **explicitly decompose** a criterion into its separate atomic
requirements (e.g. "accurate AND complete AND mentions contraindications"
→ three separate yes/no questions). That gives an exact, checkable
prediction Probe D never had: if Jev reasons consistently, the compound
answer should equal "atomic 1 AND atomic 2 AND ...".

**The catch we almost got stuck on:** the physician label is for the
*whole* criterion — it doesn't say which atomic piece failed, so it looks
like you need 100–200 hand-labeled atomic examples before you can test
anything. That's true for a *different* question ("was this specific
atomic judgment correct"). It's not true for the one we actually needed:
"does decomposition inconsistency predict that the *compound* judgment is
wrong" only needs the compound label we already had. No new annotation
required — just a cleaner probe.

**Decision, and the ordering mattered:** decompose and validate every
criterion from text alone, *before* looking at any Jev output. Freeze that
file. Only then run Jev on the atomic pieces. This wasn't a formality —
if you decompose criteria after seeing which ones look interesting, any
result is contaminated by selecting on the outcome you're testing.

**Result:** out of 30 criteria, a second model confirmed only **8** had a
genuinely complete, non-overlapping decomposition — most attempts came
back either missing a requirement or double-counting one, which is itself
a small, honest finding about how hard this is to get right even when
you ask explicitly instead of hoping for an implication. Those 8 covered
113 pairs. Running the same statistical pipeline as Probe D (standalone
check, nested models, likelihood-ratio test, bootstrap, cross-validation):

- Confidence alone: AUROC 0.724. Confidence + decomposition gap: 0.753.
- Likelihood-ratio test: p = 0.095 — doesn't clear significance.
- Bootstrap on the improvement: 95% CI **[−0.007, 0.123] — includes zero**.
- Cross-validated: 0.696 → 0.710, 95% range **[−0.004, 0.028] — includes zero**.
- The accuracy comparison even pointed the wrong way (87.5% vs. 78.7%),
  but with error bars wide enough to swallow the difference whole.

**This does not replicate Probe D's result.** And that's informative on
its own: it suggests Probe D's earlier power came substantially from its
construction flaw (the accidental narrowing audited in section 9), not
from decomposition-inconsistency being a generally powerful signal.
It's not a clean disproof either — 113 pairs and only 24 inconsistent
cases is thin enough that a real effect the same size as Probe D's would
still be consistent with these numbers. The honest conclusion is "not
resolved, and not the free general-purpose trick we were hoping for" —
which is exactly the result that should stop you from searching for a
different formulation until you get the answer you wanted.

## 12. This isn't new territory

Two real, verified papers turned up while sanity-checking our own framing
against prior work:

- Srikanth, Carpuat & Rudinger (TACL 2024) built ParaNlu, nearly 8,000
  human-validated paraphrases of reasoning problems, and measured
  *paraphrastic consistency* — how often a model gives the same answer to
  two different wordings of the same problem. Their finding: no model has
  both high accuracy and high consistency, even the good ones.
- Srikanth & Rudinger (NAACL 2025) followed up by decomposing reasoning
  problems into atomic sub-propositions and found the same pattern one
  level down — models "still struggle with logical consistency" on the
  individual pieces, not just the whole problem. They also explicitly flag
  that not every atomic piece is equally determinative of the final label
  — the same scope issue our own audit (section 9) ran into independently.

Neither paper contradicts what we found, because they're measuring a
different property. Both ask "how consistent is this model, in aggregate,
across a benchmark" — a property of the model. We asked "does *this one*
disagreement, on *this one* example, tell me *this* answer is probably
wrong" — a property of the signal. A model can be imperfectly consistent
exactly the way those papers describe (Jev's own A/B paraphrase probes
agreed only ~89% of the time, not 100%) while that imperfection still
carries close to zero information about which individual answers are the
wrong ones. Consistency and diagnosticity are not the same property.

## 13. Final state

| Claim | Status |
|---|---|
| "Paraphrase disagreement signals uncertainty" (the original idea) | ❌ not supported |
| "Jev's logical self-contradiction reveals its errors" | ❌ not established |
| "A structured sub-question can reveal Jev errors beyond its own confidence" | ✅ real for one specific (flawed) probe — did not survive being replaced with a cleaner version |
| "Clean, explicit criterion decomposition is a reliable error signal" | 🤷 unresolved — not enough clean examples (113 pairs, 24 inconsistent) to say either way |
